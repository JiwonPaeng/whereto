> DB에 들어가고 그 위에 투표가 쌓이면 되돌리기 어렵다.

## 채우는 법

**대학 홈페이지의 학과 목록을 그대로 옮겨 적고, 계열 하나만 고른다.**

| 대학 | 실제 학과명 | 계열 |
|---|---|---|
| 고려대 | 컴퓨터학과 | 공학 |
| 고려대 | 인공지능학과 | 공학 |
| 고려대 | 경영학과 | 사회 |
| 연세대 | 언더우드학부 | 사회 |

- **실제 학과명** = `programs.display_name`. 홈페이지 표기 그대로. 화면에 이대로 나온다
- **계열** = 아래 7개 중 하나. 이게 우리가 하는 분류의 전부다
- 학부 신입학 모집이 없는 곳(전문대학원만 있는 경우)은 **적지 않는다**

### 계열 7개

```
인문   사회   자연   공학   의약   사범   예체능
```

**그 대학에서 실제로 어느 단과대에 속하는지를 기준으로 고르시면 됩니다.** 대학마다 달라도 됩니다 — 통계학이 어느 대학에선 자연과학대학, 다른 대학에선 정경대학인 것을 그대로 반영하면 됩니다. 이전 버전에서 "같이 정하자"고 했던 통계학·심리학·식품영양학 문제는 이 구조에서 사라졌습니다.

### 표준 학과는 더 이상 없습니다 (D-007)

이전 워크시트는 `컴퓨터학과 → 컴퓨터공학` 같은 표준 분류를 함께 고르게 했는데, 그 계층을 없앴습니다. §5.4 매칭이 계열과 ELO만 쓰고 학과 단위 순위는 §4.3에 없어서, 매핑 비용에 상응하는 이득이 없었습니다.

**학과명은 정규화하지 마세요.** 홈페이지에 적힌 그대로가 정답입니다.

## 아직 판단이 필요한 것 하나

**자유전공·광역 모집단위** (자유전공학부, 융합인재학부, 언더우드학부 등)를 Program 으로 넣을지.

- 넣으면: 실제 모집단위이므로 수험생의 선택지로 자연스럽다
- 안 넣으면: "학과 선호도"라는 정의가 흐려지지 않는다
- 넣는다면 계열을 뭘로 볼지도 정해야 합니다 (모집 계열을 따르거나, 별도 취급하거나)

이건 §1.2 투표 질문의 의미에 닿는 문제라 임의로 정하지 않겠습니다.
